# 执行摘要：MLS-MPM 流体内核迁入 Python（批次 4 第一半）

## 动机
> 用户 2026-10-08 拍板：**MPM/FEM 迁 Python（接受 2.5–4× 的慢）**，并要求在每个工具上
> **标记"后续 Rust/C 加速"**（原生属中后期）。本轮做 MPM 的**内核**这一半：它是纯数组算术
> （P2G 散射、弱可压 EOS、网格更新与边界条件、G2P 仿射动量传递、平流与出口规则），
> 零平台依赖。半区切分是为了可验证：内核先证明数值对得上，下一轮再接 `simulate_fluid` 工具层。

## 影响范围

## 具体操作步骤
> 1. **状态留在 worker 里，按 id 寻址**（不在 IPC 里搬状态）：pos/vel/C 是每粒子 28 字节，
>     564k 粒子的验收用例就是 15 MB —— 远超"大载荷走文件"那条线。调用方交一次种子，
>     之后只问统计量。
> 2. 逐段镜像 `mpm.ts`：确定性抖动（同一个正弦哈希，**不用 RNG**）、`calibrate`
>     （质量 P2G → 占用格中位数密度，前 8192 个 m>0.2 采样）、P2G 质量/动量、应力
>     （EOS `stiffness*max(0, dr⁵-1)` + 粘性 `μ(C+Cᵀ)`，`volume*-4*dt` 缩放）、
>     网格更新（`v=mom/mass`、边界法向速度归零、实体掩码主法向归零）、G2P
>     （**实体格从插值中剔除并重新归一化**，否则近壁粒子被人为边界层拖住）、重力、CFL 夹紧、
>     入口驱动、NaN 守卫（清零 C，否则毒化的仿射矩阵每步重播 NaN）、平流与箱体夹紧、
>     出口回收/逃逸（逃逸后压缩活动粒子）、`lastStep` 诊断。
> 3. **向量化**：27 格模板用 `np.bincount` 散射、应力整段向量化（无逐粒子 Python 循环）。

## 预期风险与验证
> - **风险点：数值不可比**（numpy 向量化的求和顺序 ≠ TS 的顺序累加；`np.sin` 与 `Math.sin`
>   末位不同）。处理：**分层验收** —— 配置类结果必须一致、聚合量必须紧、逐粒子状态只报证据。
> - **验证结果（`accept-mpm-parity.mjs`，全过）**：
>   - 标定静止密度：Δrel **7.6e-8**
>   - 平均速率 TS 3.417821 → py 3.417826；总动量、位置和 **Δrel 1e-8~1e-7**
>   - **逐粒子漂移：40 步后 max |Δpos| = 9.8e-6 格 = 4.9e-6 mm**，max |Δvel| 3.3e-5 格/s
>     —— 即两侧在同一内核里只差 float64 求和顺序的噪声
>   - 逃逸/回收/入口规则：计数一致；**入口确实驱动了流动**（判别用例：静止 3.42 → 驱动后更高）
>   - 非有限事件 0、活动粒子数一致
> - **性能（已知且已被用户接受）**：小世界上 Python **4.7–6.3×** 慢于 TS 内核
>   （此前基准 2.5–4×；小世界每步 numpy 开销占比更高）。**原生上限实测比 TS 快 3.7–4.6×**，
>   所以"标记后续 Rust/C 加速"落在工具层接线时一并加上。
> - **未完成（下一轮）**：`simulate_fluid` 工具层（`fluid.ts` 的投影/回流守恒审计、
>   时均分速、渲染帧）接线 + **`accept-m4` 24/24 重跑** + 工具上的"后续加速"标记。
