# 文档地图

三类读者，三个目录。**同一件事写给不同的人，内容不一样**；不复制，只链接。

| 读者 | 入口 | 回答的问题 | 不写什么 |
|---|---|---|---|
| 用户 | `docs/user/` | 我怎么做、我该看什么、我该决定什么、它做不到什么 | 工具清单、字段、JSON、引擎内部 |
| LLM / Agent | `skills/` → `docs/llm/` → `docs/TOOL-CONTRACTS.md` | 下一步用哪个工具、字段什么意思、什么不能声称 | 安装、营销、教程 |
| 维护者 | `docs/dev/` + `HARNESS.md` / `DESIGN.md` / `docs/DECISION-LOG.md` | 为什么这样设计、契约是什么、历史取舍 | 用户教程 |

## 权威顺序

一个事实只在一个地方定义，其他地方链接：

1. **工具 schema / `docs/TOOL-CONTRACTS.md`** —— 参数、字段、返回形状（生成物，不手改）。
2. **`skills/`** —— Agent 的入口：路由、短规则、陷阱、停止条件。
3. **`docs/llm/`** —— 长解释、引擎边界、交付纪律全文；skill 只留一句指针。
4. **`HARNESS.md` / `DESIGN.md`** —— 为什么这样设计、当前架构。
5. **`docs/DECISION-LOG.md`** —— 历史取舍（append-only，不回改）。

## 用户文档不写 30 个工具

用户不选工具，用户选**结果**。用户文档只写四件事：

- 你会看到什么（面板、版本、报告、回放）；
- 你要决定什么（意图、取舍、验收）；
- 工具不替你决定什么（工艺选择、合格证）；
- 它做不到什么（边界）。

工具名、参数、JSON 字段属于 `docs/llm/` 和 `docs/TOOL-CONTRACTS.md`，不进用户文档。

## 同一主题的两版（示例：可打印性）

**用户版**：交付前每个零件会做可打印性检查，报告会指出“哪里太薄、哪里需要支撑”。它按你声明的工艺判断，不会替你选工艺，也不会给“合格证”。

**LLM 版**：`check_printability` 采样壁厚 + 精确悬垂面积；`wallMeasured:false` 时永不通过；`not-excluded` ≠ 可制造；未声明 profile 时用内建回退并降级；每次检查写 run。

两版说的是同一件事，但**读者拿它做的事不同**，所以内容不同。

## 目录

| 路径 | 内容 |
|---|---|
| `docs/user/` | 用户指南：它是什么、工作流、审阅、边界、排错 |
| `docs/llm/` | Agent 参考：引擎边界、陷阱、交付纪律、约定（长解释） |
| `docs/dev/` | 维护者入口：架构、设计、决策历史、UI 计划、审计 |
| `skills/` | Agent 的任务入口（短规则 + 路由 + 指针） |
| `docs/TOOL-CONTRACTS.md` | 30 个工具的参数/字段权威（生成物） |
| `README.md` | 项目门面：安装、快速开始、常见问题 |
