## 0. 一句话结论

面板今天是一台**只读的证据浏览器**；而「准生产力工具」的门槛是**能判、能要、能留**。
它把「找 → 判 → 要 → 留」四件事里的第一件做到了可用，后三件基本都退回给了对话。

更准确地说：**UI 落后宿主一个身位**。宿主这两周把判定词汇、按运行寻址、人工触发路由、
审计与预检都做出来了，面板还在用上一代的数据形状（`status`、`?v=`、只有流体一键）。

## 1. 结构性诊断（五条）

### 1.1 它只有两个写动作，其余全是读 `[静态]`

客户端全部网络调用里，**POST 只有三处、两个能力**：
`/api/cad/import`（登记外部文件，对话框与面板各一处）与 `/api/cad/fluid/run`
（以当前版本跑流体）。

没有：批准 / 否决 / 回滚 / 重命名 / 删除 / 备注 / 改参数 / 改装配清单。
宿主有**触发运行**的写路由（`fluid/physics/motion/assembly/run`、`import`），
但没有**改变产物状态**的路由——`status` 恒为 `draft`，这是审计 §8 核对过的现状。

**后果**：人的每一次「改」都要退回聊天框，用自然语言描述，再等一轮。
`DESIGN §30.16` 已把「权威编辑」记为待建——这不是新发现，但它现在是**最大的时间成本**。

### 1.2 宿主已经建好的门，UI 没有开 `[静态]`

这是本清单里最便宜的一批工作，逐条列在 §4 表 L0。摘要：

| 宿主能力 | 路由 / 字段 | 面板现状 |
|---|---|---|
| 按**运行**取注意力场 | `GET /api/cad/run/attention?id=` | 用的是按版本取的旧路 `?v=`（AUDIT E5 未修） |
| 装配契约检查 | `GET /api/cad/assembly/check` | 零调用 |
| 版本清单 | `GET /api/cad/manifest` | 零调用 |
| 成本遥测 | `GET /api/cad/usage` | 零调用 |
| 物理 / 机构 / 装配的人工触发 | `POST /api/cad/{physics,motion,assembly}/run` | 零调用（只有流体接了「一键跑」） |
| **参数编辑三件套** | `GET /api/cad/params`、`POST /api/cad/preview`、`POST /api/cad/apply-params` | **零调用，且 AUDIT E1 计划当死代码删掉**（见 §14 决策 1） |
| `supersedes`（被谁取代） | `RunProduct.supersedes` | 只在 tooltip 里显示 `supersededBy` |
| `pythonOverlay`（这次运行用了哪些额外包） | `RunProduct.pythonOverlay` | 零显示 |
| 过程档案 / 阈值出处 | 工具输出 | 无 UI |

**后果**：模型侧的能力在涨，人侧能看见/能触发的没变。这会让"人机两半"越走越远。

### 1.3 找不到 `[实测]`

语料规模（本次数的）：

| 语料 | 版本 | 零件 | 运行 |
|---|---|---|---|
| `examples/microscope5` | 83 | 16 | 70 |
| `examples/toy-balance2`（当前 `cad-data`） | 30 | 18 | 69 |
| `examples/microscope4` | 57 | 16 | 40 |

导航是 **5 个类目 × 原生 `<select>`**：工作目录 / 种类 / 条目 / 记录 / 跟随。
没有搜索、没有过滤、没有最近访问、没有时间线、没有跨类目跳转；零件和它自己的运行
分在不同类目里。找一版 = 在 83 个 `<option>` 里肉眼扫。

**后果**：语料越大，面板越像"翻箱底"；人会退化成"问 Agent 那一版叫什么"。

### 1.4 判读被压在最小的位置 `[静态]`

- 权威三值（否决 / 困难 / 不排除可行）**只出现在底部状态带**：`judgementGlyph` +
  `VERDICT_WORD`，11px 单行，还和一个更长的 `statusIdentity` 抢宽度。
- 列表与浏览行里显示的是 `status` 的 emoji（`statusGlyph`：✅/❌/⚠️）——**两套词表并存**，
  而 `status: 'pass'` 恰恰是审计 B5 那个「风险图没发现问题 → 显示通过」的病灶来源。
- 报告是 `div` 文本流（`runReportBody`，六种 kind 各一段 `line()`）；唯一的结构化表是
  装配契约那段手写 `<table>`。报告盒固定 190px、会滚。
- 热力图图例写的是数值含义，**没有写这份场来自哪次运行**（E5）。

**后果**：人最需要的结论最不显眼；"这版能不能用"要逐条点开运行去拼。

### 1.5 没有设计系统，也没有 UI 护栏 `[实测]`

| 指标 | 数值 |
|---|---|
| `panel.ts` 行数 | 3111 |
| `React.createElement` 调用 | 198 |
| 内联 `style: {` 对象 | 121 |
| `useState` | 48 |
| `src/client/**` 不同十六进制颜色 | **73** |
| 字号声明 / 其中 11px | 91 / **53** |

沙箱已有 `assert=layout` / `assert=local-import` / `assert=insert`，但**没有**
「每个类目 × 每个页签 × 每种宽度」的场景矩阵，也没有像素基线。

**后果**：每加一个控件都是一次手工排版；回归只能靠人眼，而人眼看的还是逐张手工拍的图（出图链路已于 10-23 晚恢复，但仍无矩阵、无基线）。

## 2. 目标：四个动作，一套界面

**先认一条环境事实**：面板是一个 **320–520px 的右栏 Tab**（`sidebar.right.pane.tab`），
不是整页应用。所以目标形态必须是**窄栏优先**——不能照搬"左树 / 中视口 / 右证据"三栏。
三栏只在"面板放大到整页"时成立，而整页形态需要宿主提供位置（**未验证**，见 A8）。

窄栏形态（自上而下，仍是今天的分段，只是每段换了内容）：

```
┌───────────────────────────────────────────────┐
│ 显微镜 · 调焦滑座  v030 ▾        ⌘K   ⋯        │ ← 面包屑 + 搜索 + 更多
├───────────────────────────────────────────────┤
│ ● 不排除可行 · 2 次验证 · 1 条证据过期  →      │ ← 判定条（从底栏提上来）
├───────────────────────────────────────────────┤
│                                               │
│  [📸 ▭ 📏 ▤ ◐ 🔥]      视口                    │
│                                               │
├───────────────────────────────────────────────┤
│ 证据 / 缺口 / 报告 / 更多                     │ ← 页签，内容结构化（4 个是窄栏上限）
│ （固定高度，可 ⤢ 浮层）                        │
├───────────────────────────────────────────────┤
│ 重跑 · 对比 · 批准 · 改参数 · 发请求 · 导出     │ ← 动作条（今天的空白）
├───────────────────────────────────────────────┤
│ r003 · 清单检查 · 09-28 16:08 — 3 接口 …      │ ← 状态带
└───────────────────────────────────────────────┘
```

"找"不再靠一行下拉：面包屑点开是**导航浮层**（搜索 + 零件树 + 运行列表 + 未登记），
浮层不占版式——这是今天已有 `sheet` 机制的直接复用，不是新概念。

四件事，每件都有明确的"完成判据"：

| 动作 | 今天 | 要做到 |
|---|---|---|
| **找** | 5 个下拉 | 3 次按键内定位任意零件/版本/运行 |
| **判** | 底栏一个词 | 打开即知"能不能用、缺什么、证据过没过期" |
| **要** | 截图 + 自由文本 | 结构化请求（版本 + 几何指向 + 实测 + 目标）一键进会话 |
| **留** | 无 | 批准/否决/备注落盘，可追溯，可对比 |

> **A8（前置问题，不是条目）**：面板是否需要"整页形态"？
> 三栏、对比视图、大装配都在这条上。当前只在右栏注册了一种 tab 类型
> （`src/client/index.ts` 的 `TAB_ID`/`TAB_KIND`），**能否注册中心区 tab 或全屏浮层，未验证**。
> 这条不解决，B5 对比与 E2 装配表达只能挤在 380px 里做。

### 2.1 注意力原则（2026-10-23 拍板，见 DECISION-LOG 同日条目）

**工具引导模型的注意力，模型只能请求人的注意力。** 两者失败模式不同，手段就必须不同：

| | 模型的注意力 | 人的注意力 |
|---|---|---|
| 不引导的后果 | 漏检（该看的没看） | 迷失（被打断、被细节带走） |
| 正确手段 | 强制指向（HARNESS §11.14：检查/仿真工具不许沉默） | 可拒绝、可延后的请求（队列 + 计数） |
| 禁止的做法 | 让模型自己想起 | 把视图直接推给人 |

**直接后果**（都进表 R）：待阅队列取代推屏；`followLatest` 默认关；面板不再自动弹出；
模型不能撤回已投递项；"回到原图"是一等功能。

## 12. 怎么判断这件事做完了（北极星判据）

不是"功能齐全"，而是**一段真实使用里，人因面板做不到而退回聊天的次数**：

1. 打开面板 **5 秒**内，说出当前产物是什么、判定是什么、证据是否过期。
2. **30 秒**内，用键盘找到任意一版 / 一次运行（不许用下拉扫）。
3. 不离开面板完成：重跑一次检查、发一个带几何指向的请求、导出。
4. 连续使用 **2 小时**，因"面板做不到"而切回聊天框 **≤ 2 次**（人工计数，可复现）。

第 4 条是这套改造真正的验收；前三条是它的分解。

## 13. 明确的非目标

- **不做浏览器内的布尔/建模内核**。几何只由 `generate_part` / `import_part` 产生。
- **不让面板成为第二个真值来源**。任何写入都走宿主已有的 job 函数；面板不自己造版本、
  不自己算判定、不自己写 manifest。
- **不引入第二套判定词汇**。三值只从 `shared/judgement.ts` 来。
- **不为每一种报告写一个渲染器**。一套数据驱动渲染器 + 每 kind 一个 schema。
- **不为了好看加图表库**。先有判据，再谈样式。
- **单位制保持 mm**，不做英制切换（与全站一致）。

## 14. 需要拍板的五件事

1. **面板的定位**：只读证据浏览器，还是工作面（含审批与编辑）？
   这件事已经有一个具体的岔口摆在面前：`/api/cad/{params,preview,apply-params}`
   **参数编辑三件套已经写好、零调用**，`AUDIT E1` 判它是"死代码，删"，本清单把它列为
   L9 / D5。两条路只能选一条——删掉，等于承认面板只读；接上，面板就有了第一个「改」。
   建议：**接上**（复用现有实现，UI 约 2–3 天），并在界面上写明它只处理顶层标量。
   D5 的"约束保持编辑"再单独拍板。
2. **"批准"写在哪**：版本是不可变提交，批准只能加旁路标签。
   落 `manifest.json` 的 status，还是旁路 `notes.json`？（建议旁路，manifest 保持纯版本事实）
3. **导航形态**：导航浮层（搜索 + 树，替换三个下拉），还是保留三段下拉只加搜索？
   前者一次到位但改动大；后者便宜，83 版的痛点只解一半。建议前者，且**必须**复用现有
   `sheet` 浮层机制（浮层不占版式，视口不会跳）。
4. **要不要整页形态**（A8）：380px 里做不了版本对比、爆炸视图、大装配。
   需要先查清宿主是否允许注册中心区 tab 或全屏浮层；**查清之前，B5/E2 不能开工**。
5. **改造方式**：strangler（保留数据层与路由，只换表现层）还是重写表现层？
   建议 strangler——数据层（products/runs/verdict）是这段时间刚校准过的，别动。
