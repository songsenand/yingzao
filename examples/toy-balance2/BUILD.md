## 7. 工作行程运动证据

`simulate_motion` **r102**（r013 的 24 位姿重跑）：驱动件 = 横梁组 v026（kinematic，pivot (0,0,101)，绕 +Y，ω=0.5 rad/s），固定件 = 底座 v001；`cycles = 0.03` → **0.188 rad = 10.8°**；754 步 / 0.377 s；**24 个采样位姿、25 帧、最大关节漂移 0 mm**。旧 r013 只有 1 个采样位姿（t=0），已不能作为运动证据。

- 只跑工作行程：单向 0→10.8°（覆盖 0→8° 工作点；另一侧按几何对称、未跑），停在 12.1° 机械死点之前。
- 死点 12.1° 是**手算**：横梁底面（z=106）在立柱顶块棱（x=±9, z=104）上方，转过 θ 后间隙 = 5cosθ − 9sinθ − 3 = 0 → θ = 12.1°。刀口斜面接触 V 面要到 17.1°，所以**先碰到的是梁体，不是刀口** —— 刀口在整个行程里始终是单线支承。
- 托盘/吊架**没有进运动场景**：运动引擎无重力，用关节把吊架挂上去它只会跟着横梁转（伪干涉）；真实吊架是摆，位姿由重力决定（始终竖直）。托盘系统改用 **validate_assembly r046**（23 件 253 对，0 干涉 0 过紧）+ 几何论证：托盘最低点 z=65.9 与底座顶面 z=20 相距 45 mm。
- **过期证据的例子**：r005 是我对 v019 的第一次运动运行，横梁组改成 v026 后 `check_assembly` 直接判 `STALE: it verified v019, which a part has since replaced`。这条纪律很值——自那次之后所有整机级结论都按当前版本重跑过。

- **r101 是无转动副的诊断，不是缺陷**：同一 0→10.8° 扫掠拿掉 `底座↔横梁组` 转动副后，24/24 个位姿都报该对重叠 **0.002→0.034 mm³**（10.8° 时约 0.037 mm，位置 z≈101、y∈[−5,5]），这是刀口 V 根部 0.4 mm 平台的**名义就位**，正是 `motion.ts` 排除转动副连接对的原因。r101 的 fail 是诊断结果，保留它是为了证明采样在该对上真的生效；正式运动证据是 r102。

- **warn stale-evidence**：早期探针运行引用了后来被取代的版本。真实的修复动作已经做了——r044（装配，历史假绿）、r046（净间隙）、r102（运动）引用的都是当前版本；现行装配契约判定是 r104。
- **info duplicate-runs**：16 次运行花在 manifest 结构探针上（见 §10 第 1 条工具批评）。

早期一次审计（在修完干涉之前）还报过 `failing-assembly: r045 干涉 2 · 过紧 26`。那 2 处是自攻名义过盈、26 处是 0 间隙座面接触；`validate_assembly r046` 用 `clearanceThreshold: 0` 并**把 2 只自攻螺钉排除**后是 0/0 全绿——**排除动作明说在此**：自攻螺钉靠材料变形固定，不是间隙配合件，把它放进间隙扫描只会得到"螺纹咬合"这一个必然的红。25 件全量结果 r045 也保留在语料里，两者都可查。

## 10. 技能 / 工具：帮到、误导、明显错误（逐条）

### 帮到我的
1. **`check_assembly` 的"未声明邻接"发现通道，一个不漏地抓出 5 个真缺陷**（每一个都会被我当成"能交"发出去）：
   - 螺母 10.18 mm³ × 3：我写的 `$fn=6` 在文件级被覆盖，螺母实际是 Ø6.35 圆柱，塞不进 5.5 A/F 六角坑；
   - 指针防转键 5.29 mm³：键正好挡在自己的 M3 螺杆路径上；
   - 零位滑块 21.17 mm³：C 形夹的螺钉从滑轨本体里穿过去；
   - 三臂吊架的横臂 504 mm³：横臂从**砝码本体**里穿过；
   - 吊篮竖腿 45.90 mm³ × 2：竖腿从**托盘底面**穿下去。
2. **`merge_parts` 的体积差**比任何渲染都早暴露问题：三件之和 16 916 mm³、合并后 16 628 mm³，**差 288 mm³** → 顺着这个数找到"滑块背壁在滑轨里"。图上完全看不出来。
3. **`simulate_motion` 的 STALE 判定**（r005）把"证据有效期 = 它引用的版本的有效期"这条纪律变成了一次真实返工。
4. **`measure_thickness`** 只要给一条射线，就能在叫不出曲面点的情况下拿到壁厚（本文 §8 六个数字全靠它）。
5. **profile 的 `unevaluable` / `notApplicable` 清单**让我没有把 `not-excluded` 读成"能打"——它明确说 tolMm / surfaceRaUm 是"没有需求可比"而不是"通过"，也解释了 FDM 为什么不吃 draft/escape/toolRadius 三条规则。
6. **`check_assembly` 的 run 类型报错**（"run rXXX is a physics run, not a motion run"）是唯一让我找到正确运动 run（r013，后由 r102 重跑）的线索。
7. 未声明邻接还顺手给出了**指针配重与刻度板 0.707 mm** 这个我原本没量过的读数间隙，变成了设计记录。

### 误导我的
1. **manifest 结构完全没有文档**。工具描述和 4 本 skill 都没给节点/接口格式；我花了约 10 轮、16 次运行反推出：`schemaVersion:1`、`root.kind:"assembly"`、`root.interfaces`（**不是**顶层 `interfaces`、**不是** `contracts`）、端点必须是字符串 `"节点id.datum"`、每条接口必须有 `severity`、距离期望值在 `params.distanceMm`。**一个示例 manifest 能省掉这 10 轮。**
2. **`views: []` 的行为和文档相反**：文档说 views 是"subset（子集）"，我传空数组想省图，结果**四张视图全都附上了**（5 个砝码 × 4 视图白花）。
3. **`merge_parts` 的运行被登记成 "physics run"**，让我在前 4 个 run 号里找运动运行，白猜两轮。
4. **工具没有打印姿态输入**。横梁必须翻转 180° 才能打印，但筛查器只按"工作位姿"评估，于是它报的下悬垂面其实是翻转后的上表面。这类"几何对、姿态错"的读数只能靠人解释。
5. `check_printability` 文档说"mode 只裁剪回复，不裁剪记录"——但 `judge` 模式恰恰让工具的返回**不再满足 harness 自己的输出契约**（缺 `attention`）。文档与实现互相矛盾。

### 明显错误（工具 bug）
1. **`check_printability` 在本环境基本不可用**，三种模式各错一处：
   - `judge`（默认）→ `missing required property "value.attention"`；
   - `both` + 任何有悬垂区域的件 → `"value.attention.layers[1].regions[0].triangles" is not a declared property (additionalProperties: false)`（工具内部 schema 与自身输出不一致，托盘/滑块/两个 M3 件都撞这条）；
   - 另一些件 → `value is not lossless JSON`（NaN），底座/横梁/指针/吊架都撞这条。
   → **11 个打印件只有 5 个砝码能出 verdict**。"每个零件都要 check_printability"这条交付纪律，在本环境**物理上做不到**，不是我跳过。
2. **`preflight` 直接崩**：`userExecute is not a function`。它本该是"一次调用跑完交付序列"的那个工具，本次完全没用上。
3. **文件级 `$fn` 被 harness 悄悄覆盖**。`$fn=6` 写在文件顶部时，`cylinder(d=6.35,h=2.4)` 输出的是**圆**不是六边形；只有写在调用处的 `$fn=6` 才生效。SCAD 合法、渲染看起来也对，唯一的信号就是 check_assembly 给的 10.18 mm³。
4. **空 manifest 的报错毫无指向**：`{}` 和 `{"name":"bare"}` 都只回 `Cannot read properties of undefined (reading 'id')`，不给 schema 校验信息；直到我猜出 `root` 才出现真正的 `invalid assembly manifest: schemaVersion must be 1; root must be an assembly node`。失败模式应当一次说清。

## 11. 未测（拿不到就写"未测，因为…"）

1. **刀口摩擦 / 回中角精度未测**。没有摩擦测量工具。只能给量级：k·sin2° ≈ 2.8×10⁻⁵ N·m，与刀口滚动接触的估计摩擦矩（μ_eff·N·r ≈ 3×10⁻⁵ N·m，N≈0.8 N，r≈0.2 mm）**同量级** → 回中可能停在零点附近 1–2°。这是全机最不确定的一项。
2. **±8° 极端位姿下托盘/吊架的扫掠干涉未测**，因为运动引擎无重力：用关节驱动的吊架会跟着横梁转，得到的干涉是伪的。已做的是 0° 位姿的 253 对净间隙扫描（r046）+ 托盘最低点与底座 45 mm 的几何余量。
3. **打印件实际质量未测**。体积是实测量，质量按 100% 填充 / ρ=1.24 g/cm³ 折算；实际填充率会低几个百分点。质量**比**不受影响（同材料相似体）。
4. **PLA 自攻拉拔强度未测**。指针（M3×12 自攻 9 mm）与滑块夹紧（M3×8 自攻 7 mm）都靠自攻，没有材料试验数据。
5. **0.2 mm 级定位配合的实际打印公差未测**：吊架销 Ø4.4 进托盘 Ø4.6 坑、吊眼 Ø4 套 Ø3 轴、滑块槽 3.8 跨 3.0 轨——都依赖打印机精度，需实物校准。
6. **刀口磨损 / 长期稳定性未测**。
7. **整机 v030 与横梁组件 v026 的打印筛查未测**，因为它们不是可打印件、且工具会拒绝（§10 错误 1）。
8. **整机静平衡未做物理仿真**。装配位姿取横梁 0°（几何中位）；左盘放 16 号砝码时实际会压到死点（24.2 g × 58 mm = 1.4×10⁻² N·m ≫ 回中刚度）。这是"装配位姿"而非"平衡结论"，没有用 simulate_physics 去证。
