# 显微镜 M1 试运行复盘（2026-10-01）

> **数据来源**：会话 `session-5995a2ea`（`examples/microscope`，23.3 分钟、**144 次工具调用、一个回合**、15 次 `read_image`）。
> 完整时间线导出在 `verification/microscope-narrative.md`（由会话日志的 `request/header` 与事件流还原）。
>
> **读这份复盘前必须知道的前提**：这次会话的预设是**标准模式**（不是「造物模式」）——**用户明确选了「造物模式」而且选择成功了，只是落在另一个会话上；而本插件当时还有一个"用会话头判预设"的 bug，连切换成功的会话也拿不到工具**（DESGIGN §13.14）。所以 Agent **一个 CAD 工具都没有**。
> 结论分两类，别混：**A 类（工具缺席导致的浪费）**已经修好了，重跑即可；**B 类（插件自身的缺陷）**是这次真正的收获，与预设无关。

## 1. 报错清单（4 个真实报错 + 3 个静默陷阱）

| # | 报错 | 代价 | 归因 |
|---|---|---|---|
| 1 | `skill "cad-toolbox" is unknown or no longer available` | 后续 30 次调用全部是绕行 | **两个缺陷叠加**：①出厂芯片把选择只落在"当前那个空白会话"上，41 秒后新建的显微镜会话出生即标准模式；②**本插件**用会话头（创建事实）判预设，所以连"切换成功"的会话也照样拿不到工具。详见 DESGIGN §13.14 |
| 2 | `edit: file changed since it was read` ×2 | 2 次报错 + 2 次重读 | **B 类**：先用 `sed -i`（bash）改文件、再用 `edit` 工具 → 观察快照失效。`sed -i` 即使**没匹配上**也会重写文件、更新 mtime |
| 3 | `present accepts 1 to 8 files` | 1 次重试 | **B 类**：硬件交付物天然 >8 个（报告 + 4 源码 + 清单 + 3 工具）。限制只在失败后才被知道 |
| 4 | `Cannot find module '/tmp/bottom2.mjs'` | 1 次浪费 + 重渲染 | **B 类**：`/tmp` **不跨调用**存在；而运行时上下文写的是"部分临时区域**可能**可写"，正好诱导这个错误 |

**3 个静默陷阱**（不报错，但会让人/模型误判）：

- `⏭ if-coax-lightpath: L0 check "coaxial" is unknown — skipped`，而 `overallStatus=pass` —— **声明过的接口读了像"已验证"**，其实一个算子都没跑。
- 默认邻接阈值 **0.75mm** 抓不到故意留的 **1.0mm** 让位间隙：`run r001 undeclared=0`、阈值提到 1.2 才出 `⚠ arm ↔ stage min=1.0`。模型自己写进 PROJECT.md 的"故意不声明、看邻接发现抓不抓"实验，**在默认参数下是静默的**。
- `declared` 判定按**零件对**而不是按 datum 对：模型第一版把 `chain-u` 写成跨 `arm↔stage` 的高度链自检 → 这一对从此"已声明"，1.0mm 间隙在**任何**阈值下都不再被报出来（它用 1000mm 阈值实验 + 改源码打 DBG 才定位）。修正方式是把它改成**零件内**自检。

## 2. A 类：工具缺席的账（已修，但要记住代价）

- **30/144 次调用（21%）、前 8.3 分钟**全部用于逆向工程插件自己的 API：读 `compile.ts` / `version.ts` / `assembly-check.ts` / `runs.ts` / `manifest.ts` / `products.ts` / `tools.ts`、找 openscad 二进制、探测挂载点是否可写。
- 因为没有工具，它**自己重建了一整套**：`tools/probe.mjs`（≙ `generate_part`）、`tools/build-m1.mjs`（≙ 工具链 + 版本库）、`tools/pair-distance.mjs`、`tools/negative-control.mjs`、`tools/render-assembly.mjs`。
- 因为工作区外只读，它把语料写到了**自己的**数据根 `examples/microscope/cad-data/`（6 版本 / 5 运行 / 4 零件），**没有**进插件语料 —— 所以面板里看不到这次 M1。它的 README 给了导入命令：`CAD_DATA_ROOT=<harness>/data node tools/build-m1.mjs`。

**结论**：这不是模型的锅，但它证明了**工具表缺席的代价不是"少几个功能"，而是把所有能力都换成了管道工**。

## 3. B 类：模型自己造出来、其实应该是插件功能的东西

按价值排序。这三个都是模型**自发**写的，说明需求真实存在。

### 3.1 校验器自证（`negative-control.mjs`）—— 本次最有价值的模式
它主动做了两件事：把立柱止口 `Ø40→Ø39.5`（配合间隙 0.30→0.80）→ 必须 `fail`；把镜头座安装面基准抬高 3mm → `chain-u=16`、`chain-v=153` → 必须两个 hard-violation。
结果 `✅ 阴性对照全部成立：破坏被抓住`。
**为什么重要**：它把"检查通过了"从**信任**变成**取证**——"这个校验器真会失败"。插件目前没有任何机制支持这件事，模型只能自己拼。
**建议**：`check_assembly` 增加"自证"能力（如 `prove: true` / `expect: fail` 配合一处 `overrides`），或者独立工具 `verify_checker`。代价小，收益是所有后续结论的可信度。

### 3.2 装配体没有图给模型看
`generate_part` 给 4 视角，`simulate_*` 给关键帧，`measure_closest` 给标注图——**唯独 `validate_assembly` / `check_assembly` 一张图都不返回**。模型想"看一眼装起来对不对"，只能自己写 `render-assembly.mjs`（临时 SCAD 导入 4 个 STL + 清单变换 → 900×900 四视图）。
**建议**：装配检查的 run 已经存了每个零件的 STL 与 `placements`（面板就是靠它渲染的），**渲染一张装配图并作为 image block 返回**只是复用现有渲染路径（`physics.ts` 的关键帧渲染已经这么干了）。这是投入产出比最高的一项。

### 3.3 独立复测（`pair-distance.mjs`）
模型不信任"清单自己算出来的数"，于是**绕过清单**直接量 STL 的六对距离，再和清单对账（结果一致：0 / 0.30 / 1.0）。
**建议**：给 `measure_*` 或装配检查加一个"独立通道"语义，明确"这条路径不经过清单"，让"两套独立方法给同一个数"成为**工具支持的取证**，而不是模型的自选动作。

## 5. 建议的动手顺序

1. **装配体渲染图返还给模型**（3.2）—— 补上"验证循环里唯一没有眼睛"的一环。
2. **`skipped` 不许混进 `pass`**（§1 静默陷阱 1）—— 声明的接口被静默跳过，是比"失败"更危险的失败。
3. **邻接发现要报"最近的一对"**（§1 静默陷阱 2）—— 即使没超阈值，也报 `最近的未声明邻近 = 1.0mm（阈值 0.75）`，让"差点抓到"可见；默认阈值也该按"常见让位间隙"重定。
4. **`declared` 判定下沉到 datum 对**（§1 静默陷阱 3）。
5. **校验器自证**（3.1）作为一等工具。
6. 文档级：`present` 上限写进工具描述；运行时上下文把"`/tmp` 部分可写"改成"**不跨调用**"。

> 前 4 项都属于"让模型收到的反馈更真实"，而不是"给模型更多功能"——对发挥 LLM 能力来说，**反馈的质量比工具的数量更重要**。
