# 01b · 诊断：上一轮到底交付了什么

`dossier/` 里是上一个会话留下的全部**客观证据**，原样拷贝，未经整理：

```
dossier/
├── assembly.json            ← 它写的装配清单
├── cad-data-manifest.json   ← 版本库索引
└── runs/<id>/
    ├── run.json             ← 每次校验运行：种类、覆盖零件、状态、一句话摘要
    └── report.json          ← 那次运行的详细结果
```

**除了这些没有别的材料**——它的项目说明与执行摘要没随交付留下。不要去找，
也不要根据"它自称做完了什么"来判断，**只看证据**。

## 请回答这五个问题

1. 它交付的**机构**（齿条-齿轮那一类会动的东西）到底有没有被**机检**过？
2. **整机**（全部交付件）的装配验证跑过吗？跑过几次？结果如何？之后的验证
   覆盖了多少件？
3. 交付状态有**整机级的视觉证据**吗？如果有，它对应的是不是最终交付的那些版本？
4. 有没有**用局部结论冒充整体结论**的地方？具体是哪一处？
5. 按优先级给出**三条最该先修的问题**，每条一句话。

## 回答的规矩

- **每个结论都要给出依据**：文件路径 + 具体字段（例如某个 `run.json` 的
  `parts` 与 `status`）。只给结论不给依据的，不算回答。
- **区分"没做"和"做了但失败"**——这是两个不同的问题，处置也不同。
- **找不到证据就说"找不到"**。不要推测，不要替它圆场。
- 不要重跑任何仿真来"验证"你的判断；这道题要的是**读证据**，不是重建。

## 交卷时要报的数

最后一并报，别铺开：

- 零件数与版本区间
- 接口统计：pass / hard / intent / undeclared（就 `assembly.json` 能读出来的）
- 工具调用轮数、墙钟、图片数
