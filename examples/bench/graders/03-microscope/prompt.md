## 参考图为什么**不**放进考生目录（GUI 档）

> **这一节只讲 GUI 档。** headless 档反过来——图就是要放进 run root，题面也写
> "工作目录下的 `参考图.png`"，因为 headless 没有把图塞进消息的通道。
> 代价是那一档测不到 `recall_reference_image`，所以 GUI 档必须留着。

B 段要测一条长程探针（`p-reference-recall`）：上下文里的附件被裁剪之后，
模型在对照参考图时会不会把它取回来。

**如果把 `参考图.png` 也放一份到 `subjects/03-microscope/`，这条探针立刻失效**
——模型可以直接 `read_image` 工作区那份副本。所以参考图**只**从评分方侧作为
对话附件发出。这与 microscope5 当年的做法一致。

A 段考卷里**已经删掉了**原来那句"参考图会被裁掉……下结论前先把它取回来"——
那句话等于把探针答案写在试卷上。

## 两段之间怎么切分

0. **发 A 段前先确认图真的附上了。** 首条 user 消息必须**带图附件**；漏了就整轮
   作废（模型看不到外形，`f-silhouette-profile` 与 `c-appearance-diff` 全都没有
   依据，而且它不会报错——只会照着文字硬猜）。这条靠人记得，所以写在这里当
   硬检查项。
1. **A 段题面发出 → 等它把 M1–M4 做完、停下来。**
2. **核对前置条件**：此时 transcript 里**必须**已经出现参考图的
   `image omitted` 占位。没有出现就说明图还在上下文里，`p-reference-recall`
   不成立 → 该探针记 `N/A` 并在结果里注明。
3. **发 B 段题面。** 它的文本固定且唯一，那条 user 消息的时间戳就是分界：
   之前的 run 归 A，之后的归 B。
4. B 段结束，分别按 `rubric.json` 里 `stage` 标记打 A / B 两个分，再算差值。

**不要**在 B 段发出前与模型讨论 A 段的结果——那会污染 B 段的"自发 vs 被要求"。

## 判据与答案

- 机检细则：`rubric.json`（12 硬门 / 12 数值 / 7 特征 / 2 探针；各条带 `stage` 标记）
- 外观地标与判据依据：`landmarks.json`（九段剖面，band4 已排除）+ `key.md`
- 参考图：`参考图.png`（530×887，水印已去）

## 本卷特别注意

1. **内部光学是自由的**，所以 M3 的判据不是具体数值，而是**说到做到**：
   `g-optics-self-consistent` 拿 `optics.json` 的声明值与 `measure_distance`
   实测值比，±0.3mm 内算过。**不要**拿 microscope5 那套 156/13.0 去卡。
2. **band4 必须排除。** 参考图第 4 段（40%–50% 高度）是物镜转换器所在的带，
   而考卷明确不许做转换器。
3. 冻结相机：方位约 35°、俯仰约 15°、纯白背景、主体占画面高度约 80%。
   A 段考卷里给了这个规格，但**没让模型去做对照**——对照是 B 段的要求。
4. `p-version-recall`（问"第 N 版载物台的槽深"）里的 N，由 runner 按语料
   动态选一个**已被图片窗口裁掉**的版本，别写死第 3 版。
