# 实验报告：球棍模型的卡扣实跑（fructose / glucose）

## 目标

> 把 `examples/ball-and-stick/` 的两个球棍模型的**卡扣**用当前插件跑一遍，回答：
>
> 1. 插件现在能不能判断“卡扣行不行”？
> 2. 如果不能，它现在实际证明了什么、没证明什么？
> 3. 用梁模型粗算，这两个卡扣在 toy-grade 上大概是什么量级？

## 方法

1. **跑 canonical `check_assembly`**：用插件的 Python canonical `runAssemblyCheck`
   （不是 TS parity oracle），对两套 `assembly/assembly.json` 跑接口检查；runs 从各自
   `cad-data` 读取。只读，不写 run。
2. **梁模型 probe**：对 fructose 用 `INTERFACE.md §5` 的尺寸重算悬臂梁；
   对 glucose 引用 `README.md §4` 的梁模型估算（其有效瓣宽/曲率未声明，不独立重算）。
3. **不把卡扣硬塞进 `spring-behaviour`**：S0 的 `spring-behaviour` 是轴向弹簧模型，
   卡扣是径向悬臂/壳；硬套会得到一个错误但“看起来像”的数。

## 结果

### 1. `check_assembly`：两套都 pass，但 pass 的不是卡扣

| 模型 | 接口数 | pass | hard-violation | intent-flag | skipped | overallStatus |
|---|---:|---:|---:|---:|---:|---|
| fructose | 122 | 122 | 0 | 0 | 0 | pass |
| glucose | 145 | 145 | 0 | 0 | 0 | pass |

但卡扣本身没有被评估：

- **fructose**：`I_B03_motion` / `I_B15_motion` 引用 r004/r005，报告
  “采样 24/24 · 干涉 0 次 · 行程 11.5/9.8mm”。这两个 run 的运动件是
  **GUIDE 件（已去掉卡扣 bead）**；它们证明的是导向、同轴、端面落座、key 唯一，
  不是“卡扣保持力”。`VERIFICATION.md` 也明确写了这一点。
- **glucose**：`行程-B02-a` 的 motion 半边 **未取证**（没有 `params.runId`），
  报告直接写 “motion half NOT evidenced”。`BUILD.md` 记录 r084 的真实行程里，
  刚性引擎把 Ø5.40 卡珠挤过 Ø5.20 喉口判成 **6 次 0.769 mm³ 干涉 → fail**；
  该 run 不作为 pass，这是引擎边界，不是设计缺陷。
- **两套清单都没有声明 `elastic` / `snap-fit` 接口**；当前也没有 snap-fit 算子。
  所以工具**看不见卡扣**，它的 pass 只是“几何配合 + 导向路径”的 pass。

### 2. 梁模型粗算（不是插件结论）

#### fructose（尺寸来自 `INTERFACE.md §5`，E=3500 MPa）

`I = w t³/12`，`k = 3EI/L³`，`F = kδ`，`ε = 1.5 t δ / L²`：

| 接口 | 瓣数 | w (mm) | t (mm) | L (mm) | δ (mm) | 单瓣 F | 合计 F | 根部应变 | 等效重量 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 重 | 4 | 8.9 | 0.8 | 4.0 | 0.125 | 7.79 N | **31.2 N** | **0.94%** | 3.18 kg |
| 轻 | 3 | 7.4 | 0.8 | 3.3 | 0.075 | 6.92 N | **20.8 N** | **0.83%** | 2.12 kg |

- 31 N / 21 N 与 `INTERFACE.md` 的 31 N / 21 N、0.94% / 0.83% 一致。
- 对约 100 g 整机（≈1 N），保持力有 20–30 倍余量；PLA+ 断裂应变通常 >3%，
  0.9% 在弹性范围内。
- 这是**上限估算**：真实杯壁是圆弧壳，载荷沿圆周分布，实际力通常更低。

#### glucose（`README.md §4` 的梁模型，未独立重算）

- 四瓣径向弹力约 **5.8 N**；经 45° 导入面与摩擦折算，插入力约 **11 N**，
  量级 **6–14 N**。
- 0.40 mm 卡脚壁、0.6 mm 开缝、卡珠 Ø5.40 过 Ø5.20 喉口、单边挤压 0.10 mm。
- 与 fructose 相比更“轻”，但仍需弹簧秤拉脱试验确认。

## 分析

1. **“pass” 不是 “卡扣行”。** 两套模型的 pass 覆盖的是同轴、端面距离、直径间隙、
   导向/落座路径；卡扣的径向弹性、插入力、保持力、根部应变都不在覆盖范围内。
   fructose 用 GUIDE 件规避了 bead；glucose 的刚性 motion 把 bead 判成干涉。
2. **当前 S0 帮不上这两个卡扣。** `spring-behaviour` 是轴向弹簧；卡扣是径向悬臂/壳。
   把卡扣写成 `axial-spring` 会得到“能算”的假象；不能这么做。
3. **梁模型给出的量级是“大概率能行”。** fructose 31/21 N、应变 <1%；glucose ≈11 N
   （6–14 N）。对人手装配是可行的，对 100 g 整机保持力也够。但这是上限估算，
   没有摩擦、接触、疲劳、打印偏差，必须按 `PRINT.md §6` 做拉脱试验。
4. **S1 的正确形状**：一个通用的 snap-fit 梁算子，而不是把卡扣塞进弹簧：
   - 输入：瓣数、瓣宽、壁厚、力臂、径向过盈、E、导入角、摩擦系数、用户力预算、
     许用应变、保持载荷；
   - 输出：单瓣刚度/力、总径向力、插入力、根部应变、十倍档位、与用户预算的比较；
   - 适用域：单悬臂/多瓣、浅倒扣、无自接触；复杂倒扣/自接触转 S4。
   这两套球棍模型正好可以当 S1 的验收夹具（尺寸、期望力、拉脱协议都是现成的）。

## 遇到的问题

1. **刚性 motion 与弹性卡扣天然冲突**：glucose r084 的 6 次干涉是引擎边界，
   不是设计缺陷；但报告如果只看 `overallStatus` 会误读。
2. **GUIDE 件规避**：fructose 用去 bead 的 GUIDE 件跑导向路径，motion pass 不覆盖卡扣；
   这是正确的工程妥协，但必须在报告里说清楚。
3. **卡扣没有被声明**：两套清单都没有 `elastic` / `snap-fit` 接口；工具没有可检查的对象。
4. **没有实测力**：梁模型是上限估算；`PRINT.md` 的弹簧秤拉脱试验还没做。

## S1 落地后的复跑（同尺寸）

S1 的 `snap-fit` 梁算子已经落地（TS/Python parity）。用上面同样的 fructose 尺寸，
在验收夹具里声明 `卡扣` 接口后，默认 L1 输出是：

| 工况 | 用户预算 | L1 输出 |
|---|---:|---|
| fructose heavy（4 瓣，w=8.9，t=0.8，L=4.0，δ=0.125，45°，μ=0.3） | 20 N | `insertion 57.85N / budget 20N = 2.8925x (over); radial 31.15N, strain 0.9375%; next: reduce bead/interference or increase the lead angle; nextLook [1.5, 10, 26.5]` |
| fructose light（3 瓣，w=7.4，t=0.8，L=3.3，δ=0.075，45°，μ=0.3） | 50 N | `all declared criteria comfortable; insertion 38.5475N / budget 50N = 0.7709x (ok); nextLook [...]` |

注意两个力的定义不同：

- **radialForceN** 是梁模型在卡珠处的径向力（fructose heavy ≈31.2 N，与
  `INTERFACE.md` 的 31 N 对齐）；
- **insertionForceN** 是经 45° 导入面和 μ=0.3 折算后的轴向插入力（≈57.9 N）；
- `forceBudgetN` 按约定是**插入力**预算，所以 heavy 在 20 N 预算下是 over；
  如果设计方把 31 N 当作插入力，应先确认他们的估算是否已含导入角/摩擦。

**仍然要注意**：两个 example 的 `assembly.json` 还没有声明 `卡扣` 接口，所以直接对
它们跑 `check_assembly` 仍然只会得到第 1 节的 fit/guide pass。要让真实模型显示 S1 结果，
需要给代表性强接口（如 `I_B03` / `I_B15`）补一条 `type: "卡扣"` + `elastic` 声明。

## 结论与下一步

- **在 S1 之前，插件不能回答“卡扣行不行”**：它回答的是“同轴/落座/直径间隙/导向路径行不行”。
  两套模型的 pass 不能当作卡扣的 pass。S1 的 `snap-fit` 现在可以对**已声明**的卡扣给出
  L1/L2 结果；两个 example 仍需补声明。
- **工程判断**：fructose 31/21 N、应变 <1%；glucose ≈11 N（6–14 N）。toy-grade 上
  大概率能装配、能保持；但必须做拉脱试验，不能把梁模型当实测。
- **S1 已实现**：通用 snap-fit 梁算子 + L1/L2 输出；两个模型作为验收夹具。
  - 输入：瓣数/宽/厚/力臂/过盈/E/导入角/摩擦/用户预算/许用应变/保持载荷；
  - 输出：径向力、插入力、保持力、根部应变、自锁、utilization、L1 attention；
  - 适用域外（复杂倒扣/自接触）仍应 `check` 并转 S4。
- **下一步**：给两个 example 的代表性接口补 `卡扣` 声明，让 `check_assembly` 直接显示
  S1 结果；再按 `PRINT.md §6` 做拉脱试验校准。
- **不要做**：把卡扣写成 `spring-behaviour` 的 `axial-spring`，或把 GUIDE 件的
  motion pass 当作卡扣证据。
