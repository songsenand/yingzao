# 实验报告：L1.0 CadQuery 可行性探针

## 目标

验证 CadQuery 2.8 能否作为 0.1.1 的第一个新增作者引擎：

- 用现有 Python 3.13 runtime 的独立 `--target` pack，不污染基础 venv；
- 编译同一个 bracket（4 孔 + fillet + datum 探针）；
- 记录 pack 体积、安装时间、import/编译/导出时间、STL 水密性、与 OpenSCAD 版 bbox 差；
- 观察 `import cadquery` 是否拉起 trame/vtk。

## 假设

- CQ 2.8 能在现有 runtime 上独立安装并编译；
- 最小 pack 约 300–500 MB；
- `import cadquery` 不应拉 trame/vtk。

## 方法

- Python：`~/.dsh/cad/runtime/venv/bin/python`（3.13.16）。
- CadQuery 2.8.0 + OCP 7.9.3.1.1。
- 安装到 `.tmp-cq-probe/pack`，命令见 `measurements.json`；`--no-deps` 显式固定包集合，**不装 trame/matplotlib**，先验证 headless 核心路径。
- bracket：60×40×6 mm 板，4 个 Ø4.5 通孔，孔位 (±22, ±13)，四条竖边 R4 圆角；顶面中心/法向作为 datum 探针。
- OpenSCAD 等价件：`offset(r=4) offset(r=-4) square([60,40])` + 4 个 `cylinder(d=4.5)`。
- STL 用 base runtime 的 `trimesh` 回读，检查 watertight / winding / body count / bbox / volume。

## 结果

### 安装与体积

| 指标 | 实测 |
|---|---|
| 安装 wall time | **196.8 s**（本机网络约 2.4 MB/s） |
| pack 全量（含 numba/llvmlite） | **1599.3 MiB** |
| 去掉 numba/llvmlite 后 | **1398.2 MiB** |
| `__pycache__` | 62.4 MiB |
| 最大组成 | vtkmodules 639 MiB、casadi 277 MiB、llvmlite 173 MiB、OCP 166 MiB、scipy 109 MiB |

### 运行时间

| 指标 | 实测 |
|---|---|
| `import cadquery` | **0.883 s**（3 次：0.887 / 0.881 / 0.883） |
| bracket build | **0.0229 s** |
| STL export | **0.0126 s** |
| 完整 CQ 脚本（含 import） | **1.284 s** |
| OpenSCAD 等价件 | **0.232 s** |

### 导入的模块

```json
{
  "trame": false,
  "vtk": true,
  "vtkmodules": true,
  "matplotlib": false,
  "pyvista": false,
  "numba": false,
  "casadi": true
}
```

结论：

- **trame / matplotlib 可以省**：`import cadquery` 不加载它们；
- **VTK 不能省**：`cadquery/occ_impl/shapes.py` 顶层导入 `vtkmodules`，STL 三角化也需要它；
- **casadi 在顶层被拉起**：`cadquery.assembly -> solver`，即使只做零件也会 import；
- numba/llvmlite 在这个 bracket 上未被 import，去掉后基础 import/compile 仍可用，但它们是 CQ 声明依赖，NURBS/vis 路径可能需要。

### 几何验证

| 指标 | CadQuery | OpenSCAD |
|---|---|---|
| bbox / mm | 60 × 40 × 6 | 60 × 40 × 6 |
| volume / mm³ | 13935.926 | 13936.018 |
| watertight | true | true |
| winding consistent | true | true |
| body count | 1 | 1 |
| faces | 2556 | 1308 |
| Euler | -6 | -6 |

- bbox delta：**0, 0, 0 mm**
- volume delta：**-0.0915 mm³（-0.000657%）**
- CQ `Shape.isValid() = true`，14 faces / 36 edges；
- datum 探针：顶面中心 `(0, 0, 6)`，法向 `(0, 0, 1)` —— 能映射到 harness 的 `point/plane` schema，但 provider 尚未实现。

## 分析

1. **功能可行性成立**：CQ 2.8 在现有 3.13 runtime 上能独立安装、编译、导出，STL 水密，几何与 OpenSCAD 等价件在 bbox 上完全一致，体积差可忽略。
2. **体积假设被推翻**：最小可用 pack 是 **1.4–1.6 GiB**，不是 300–500 MB；VTK 和 casadi 是主因，且都在 `import cadquery` 的顶层路径上。
3. **trame 问题可以消掉**：显式 `--no-deps` 固定包集合即可不装 trame/matplotlib；但 `pip install cadquery` 的默认依赖仍会拉它们。
4. **casadi 可以尝试延迟导入**：CQ 的 `assembly.py` 顶层 import solver；若上游/provider 做 lazy import，可省 277 MiB，但这是修改 CadQuery 行为，不是标准安装。
5. **VTK 无法用标准包裁剪**：wheel 是整体 `vtkmodules`；要做小包只能自编/裁剪 VTK，超出 0.1.1。
6. **时间可接受**：import 0.9 s、编译+导出 1.3 s；比 OpenSCAD 0.23 s 慢，但不是瓶颈。

## 遇到的问题

- DSH 的 bash 沙箱把 `/tmp` 当私有临时区，跨命令不保留；probe 改在 workspace `.tmp-cq-probe` 下执行。
- 直接 `pip install cadquery` 会拉 vtk/trame/matplotlib/numba 全套；本次用 `--no-deps` 显式集合做“最小 pack”测量。
- pack 的 `du` 包含 `__pycache__`；`pip --no-compile` 可再省约 62 MiB，但会牺牲启动速度。

## 结论与下一步

- **L1.0 功能通过**：CQ 能编译等价 bracket，STL 水密，bbox 完全一致。
- **L1.0 的体积假设失败**：1.4–1.6 GiB 的 pack 是产品级风险，不能当作“300–500 MB 的小增量”直接进 L1.2。
- **建议先做一个明确决策**，再继续 L1.2：
  1. 接受 1.4–1.6 GiB，按需下载/安装，并在 README/limits 明示；
  2. 先评估 lazy-import `Assembly/solver`（可省 casadi 277 MiB）和 `--no-compile`（约 62 MiB），再决定；
  3. 若体积不可接受，0.1.1 的 CQ 范围需要重谈（或改用 OCP 直连，但那就不是 CadQuery 作者层）。
- **L1.1（最小引擎 seam）与 pack 体积无关，可以继续**；但 L1.2 的 provider/pack 实现应等体积决策。
